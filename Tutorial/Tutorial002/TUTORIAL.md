## 2. Why classes?

In Tutorial 001, the player was represented by independent variables:

```csharp
string playerName = "Adventurer";
int hitPoints = 20;
int gold = 10;
```

This works for one player, but becomes difficult to maintain when the game has several characters. A **class** groups related data and behavior into one type.

Think of a class as a *blueprint* and an object as an *instance built from that blueprint*.

```text
Player class (blueprint)
   ├── Name
   ├── HitPoints
   ├── Gold
   └── ShowStatus()
          |
          +----> player object: "Adventurer", 20 HP, 10 gold
          +----> another object: "Ranger", 30 HP, 5 gold
```

## 3. Create your first class: Player

In the VS Code Explorer, create a new file named **Player.cs** next to `Program.cs`.

**Player.cs**

```csharp
namespace Tutorial002;

public class Player
{
    public string Name = "Adventurer";
    public int HitPoints = 20;
    public int MaximumHitPoints = 20;
    public int Gold = 10;
    public int ExperiencePoints = 0;
    public int Level = 1;

    public void ShowStatus()
    {
        Console.WriteLine($"Name:  {Name}");
        Console.WriteLine($"Level: {Level}");
        Console.WriteLine($"HP:    {HitPoints}/{MaximumHitPoints}");
        Console.WriteLine($"Gold:  {Gold}");
        Console.WriteLine($"XP:    {ExperiencePoints}");
    }
}
```

### Understanding the syntax

- `namespace Tutorial002;` places the class in the project's namespace.
- `public class Player` defines a class accessible from other code.
- `public string Name` declares an instance **field**.
- `public void ShowStatus()` defines an instance **method** that returns no value.
- The method uses `Name`, `Gold`, and other fields belonging to the object on which it is called.

**Important design note:** Public fields are intentionally used here to make the first class easy to understand. In Tutorial 003, we will replace them with **properties**, **constructors**, and encapsulation.

## 4. Create the Monster class

Create **Monster.cs**:

```csharp
namespace Tutorial002;

public class Monster
{
    public string Name = "Venomous Spider";
    public int HitPoints = 10;
    public int MaximumHitPoints = 10;
    public int MinimumDamage = 1;
    public int MaximumDamage = 3;
    public int RewardExperiencePoints = 10;
    public int RewardGold = 5;

    public void ShowStatus()
    {
        Console.WriteLine($"Enemy: {Name}");
        Console.WriteLine($"HP:    {HitPoints}/{MaximumHitPoints}");
    }
}
```

Both `Player` and `Monster` are **reference types** because they are classes.

## 5. Instantiate objects in Program.cs

Replace the entire contents of **Program.cs** with:

```csharp
using Tutorial002;

Console.WriteLine("================================");
Console.WriteLine("        SOSCSRPG Tutorial 002   ");
Console.WriteLine("================================");
Console.WriteLine();

Player player = new Player();
Monster monster = new Monster();

Console.WriteLine("=== PLAYER ===");
player.ShowStatus();

Console.WriteLine();
Console.WriteLine("=== ENCOUNTER ===");
monster.ShowStatus();

int weaponDamage = 4;
monster.HitPoints = Math.Max(0, monster.HitPoints - weaponDamage);

Console.WriteLine();
Console.WriteLine($"You attack for {weaponDamage} damage!");
monster.ShowStatus();

if (monster.HitPoints == 0)
{
    Console.WriteLine($"You defeated {monster.Name}!");
    player.Gold += monster.RewardGold;
    player.ExperiencePoints += monster.RewardExperiencePoints;
}
else
{
    Console.WriteLine($"{monster.Name} is still alive!");
}

Console.WriteLine();
Console.WriteLine("=== PLAYER AFTER COMBAT ===");
player.ShowStatus();
```

## 6. C# versus C++

If you know C++, these comparisons will help:

| Concept | C# | C++ |
|---|---|---|
| Class declaration | `public class Player` | `class Player` |
| Object creation | `new Player()` | `Player player;` or `new Player` |
| Field access | `player.Gold` | `player.Gold` or `pointer->Gold` |
| Instance method | `player.ShowStatus()` | `player.ShowStatus()` |
| Memory management | Garbage collector manages object memory | Often RAII / deterministic destruction |
| Multiple source files | Included automatically by SDK-style `.csproj` | Usually explicitly compiled / built |

**C# references are not C++ pointers.** A class variable refers to an object, but ordinary C# does not expose C++-style pointer arithmetic. The garbage collector manages memory, and object references can be shared.

## 7. Experiment: two variables, one object

Append this temporary experiment to the end of **Program.cs**:

```csharp
Console.WriteLine();
Console.WriteLine("=== REFERENCE EXPERIMENT ===");

Player samePlayer = player;
samePlayer.Gold += 100;

Console.WriteLine($"player.Gold:     {player.Gold}");
Console.WriteLine($"samePlayer.Gold: {samePlayer.Gold}");
```

Expected result:

```text
player.Gold:     110
samePlayer.Gold: 110
```

`samePlayer = player` does **not** clone the player. Both variables refer to the same `Player` object. This is a key difference between class objects and primitive value-type variables.

Now compare it with:

```csharp
int first = 10;
int second = first;
second += 100;

Console.WriteLine($"first:  {first}");   // 10
Console.WriteLine($"second: {second}");  // 110
```

Here, `int` is a value type, so the assignment copies the value.

## 8. Debug in Visual Studio Code

1. Open `Program.cs`.
2. Set a breakpoint on `monster.HitPoints = Math.Max(...)` by clicking in the left gutter (or pressing **F9** on the line).
3. Press **F5** and choose the C# debugger if prompted.
4. Inspect `player` and `monster` in the **Variables** panel; expand their fields.
5. Press **F10** to step over the damage calculation.
6. Confirm `monster.HitPoints` changes from `10` to `6`.
7. Continue with **F5**.

| Shortcut | Action |
|---|---|
| `F5` | Start / Continue debugging |
| `F9` | Toggle breakpoint |
| `F10` | Step Over |
| `F11` | Step Into |
| `Shift+F5` | Stop debugging |

If VS Code cannot locate .NET because another SDK is first in `PATH`, use the integrated terminal's explicit command `/usr/bin/dotnet` for builds and inspect your extension's .NET configuration. Do not switch back to the Snap SDK that caused SDL2 compatibility issues in the MonoGame project.
